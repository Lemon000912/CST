# 校园版与企业版双域名部署

项目使用同一套源码生成两个独立程序：

- 校园版前端：`dist-school`，后端端口 `8787`，固定 `APP_EDITION=school`
- 企业版前端：`dist-enterprise`，后端端口 `8788`，固定 `APP_EDITION=enterprise`

两个后端共用 PostgreSQL、JWT 密钥和用户账号。聊天记录按版本分别保存。企业版搜索、图表和 PDF 操作不扣积分，校园版继续正常计费。

企业版服务首次启动时，如果数据库中不存在 `admin`，会自动创建默认管理员：用户名 `admin`，密码 `admin123`。已有同名账号不会被覆盖；生产环境首次登录后应立即修改密码，并可在 `ailunwen-enterprise.env` 中覆盖默认值。

## 本地开发

```bash
npm run dev:school
npm run dev:enterprise
```

也可以同时启动：

```bash
npm run dev:both
```

默认地址：

- 校园版前端 `http://127.0.0.1:5175`，API `http://127.0.0.1:8787`
- 企业版前端 `http://127.0.0.1:5176`，API `http://127.0.0.1:8788`

## 构建

```bash
npm run build:all
```

也可以单独构建：

```bash
npm run build:school
npm run build:enterprise
```

## 服务器安装

确认两个域名均已解析到同一台服务器，并在项目 `.env` 或服务器私密环境文件中配置相同的 `DATABASE_URL` 和 `JWT_SECRET`。

```bash
SCHOOL_DOMAIN=school.example.com \
ENTERPRISE_DOMAIN=enterprise.example.com \
npm run install:editions
```

安装脚本使用 Apache，生成两个虚拟主机，并安装：

- `ailunwen-school-api.service`
- `ailunwen-enterprise-api.service`
- `ailunwen-pdf-sync.service`（两个版本共用一个 PDF 同步任务）

代码更新后执行：

```bash
npm run update:editions
```

## 微信登录

两个域名可以共用一个微信开放平台网站应用和一个授权回调域。数据库、JWT、短信等公共配置和两套微信配置都可以放在同一个文件：

```text
/home/ubuntu/ailunwen-secrets/ailunwen.env
```

共用 AppID/AppSecret，只用版本前缀区分授权回调和登录后的前端地址：

```dotenv
WECHAT_OPEN_APP_ID=wx_shared...
WECHAT_OPEN_APP_SECRET=...

SCHOOL_WECHAT_OPEN_REDIRECT_URI=https://school.example.com/api/v1/auth/wechat/callback
SCHOOL_WECHAT_OPEN_FRONTEND_URL=https://school.example.com/

ENTERPRISE_WECHAT_OPEN_REDIRECT_URI=https://school.example.com/api/v1/auth/wechat/callback
ENTERPRISE_WECHAT_OPEN_FRONTEND_URL=https://enterprise.example.com/

WECHAT_OPEN_COOKIE_DOMAIN=example.com
WECHAT_OPEN_ENTERPRISE_CALLBACK_URI=https://enterprise.example.com/api/v1/auth/wechat/callback
```

带前缀变量优先于旧的公共 `WECHAT_OPEN_*` 变量，旧配置仍可用于单版本部署。也仍支持把无前缀的覆盖值分别放入可选的 `ailunwen-school.env` 和 `ailunwen-enterprise.env`。

若两个版本共用 AppID，微信开放平台只需登记 `school.example.com`。企业版发起授权时也先回到该域名；带版本标识和随机 nonce 的 `state` 经父域 Cookie 校验后，只允许固定中继到 `WECHAT_OPEN_ENTERPRISE_CALLBACK_URI`，再由企业版进程完成换码和登录。不要把任意请求参数作为回跳 URL。

`WECHAT_OPEN_COOKIE_DOMAIN` 必须同时是公共回调域和企业版域名的父域（例如 `example.com`），且生产环境应使用 HTTPS。若使用两套独立 AppID，也可以继续为两个版本分别配置各自的回调域，此时无需跨子域中继。
