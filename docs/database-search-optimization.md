# 数据库搜索优化

数据库快速检索通过配置开关启用。将以下配置加入对应版本的服务环境文件，再重启该版本的后端服务：

```dotenv
DB_SEARCH_FAST_MODE=1
DB_SEARCH_BUDGET_MS=7000
DB_WEB_SEARCH_BUDGET_MS=20000
DB_WEB_FETCH_BUDGET_MS=8000
```

快速检索优先查询 PostgreSQL 的 `papers` 表；只有输入含 DOI 时才查询 `doi_records`。检索先取有限候选，再在内存中排序。外部来源并行执行，网页补充和页面正文抓取设有独立时间预算，结果入库不阻塞回答。

这些预算分别控制各阶段，不代表完整回答的总耗时上限。完整回答仍包含查询改写、外部来源和模型生成。未设置 `DB_SEARCH_FAST_MODE=1` 时保留原有数据库检索流程。

## 模型协议

如果 C 槽位使用 DeepSeek 等 OpenAI 兼容接口，还需要显式设置：

```dotenv
LLM_PROVIDER_C_PROTOCOL=openai_chat_completions
```

使用 Gemini 接口时保留默认协议，或设置 `gemini_generate_content`。A、B 槽位也支持同名的协议配置。协议配置应与对应槽位的地址、模型和密钥匹配。

已有可用草稿时，仲裁失败会返回草稿，避免重新生成整篇回答。文献分支可以提前流式输出，最终完整结果替换预览。

## 验证与回退

运行 `npm test`。新增测试覆盖查询参数绑定、短化学符号、候选排序、数据库超时后的事务回滚、连接超时释放、外部检索并行启动、协议覆盖与页面抓取取消。

将 `DB_SEARCH_FAST_MODE` 设为 `0` 并重启服务，可回退数据库快速检索、并行调度和抓取预算；模型协议与回答回退逻辑独立于该开关。完全回退需恢复部署前代码和服务配置。

服务密钥和生产环境文件不应提交到仓库。
