# 会话同步修复与恢复

此次修复针对部分历史缺失、终稿在会话中仍显示生成中，以及重复整份历史上传的问题，校园、企业、金融版共用。

- 前端按内容指纹只上传变化的会话，串行保存，飞行期间的新变化排队补存。服务端确认版本不会再次触发上传。409 时按消息 ID 合并、保留终稿后重试；网络失败保留待保存状态并提示、重试。
- 本地使用按用户、版本、会话隔离的 IndexedDB，兼容既有 localStorage；大历史不会只因 localStorage 超额而无法保存在本机。全文不再按 12000 字符截断。
- 服务端按用户与版本锁定同步事务，合并消息，终稿优先于旧草稿；无内容变化不递增版本。删除会话保存持久标记，旧客户端不能复活它。
- 新检索请求携带会话及用户/助手消息 ID。终稿保存与结算处于同一事务，保存失败则一起回滚。旧客户端未传 ID 时，只更新已明确关联该操作的现有会话，不擅自创建可能已被用户删除的会话。
- 可见页面每 30 秒及重新聚焦、网络恢复时核对服务器版本；无变化只返回版本状态，有变化再合并。登录过期或保存失败显示同步提示。

验证：消息级冲突合并、终稿保护、网络恢复、飞行期间补存、不重复保存、删除保护、计费与历史原子回滚；真实浏览器大历史/刷新恢复和增量上传；PostgreSQL 三版本并发写入。UI 测试使用隔离浏览器及模拟接口，数据库测试使用隔离 schema 并在结束后移除。

部署会备份当前后端文件、前端站点配置与目录、历史数据库表。回退恢复应用文件和站点配置，新增删除标记表与已保存的新历史保留，不用旧数据库快照覆盖上线后产生的记录。

指定账号的恢复仅处理已核实的两次操作：用户本轮提供及核实的两次操作（恢复脚本显式限定用户、版本和操作白名单）。恢复前备份会话与操作快照，从已保存的计费结果恢复终稿及引用，按操作 ID 去重、尊重删除标记，不重新扣费，不更改余额及原计费操作。未核实是否为主动删除的旧记录不会批量恢复。
