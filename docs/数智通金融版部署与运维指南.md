# 数智通金融版部署与运维指南

本文面向将「数智通金融版」部署到 Ubuntu 生产服务器的运维人员，涵盖部署、支付与登录配置、验收、更新和日常维护。金融版使用仓库内的 `dist-finance` 前端和独立 API 进程，默认监听 `127.0.0.1:8789`，通过 HTTPS 域名向用户提供服务。

> **当前部署脚本说明：**仓库提供的生产安装脚本是三版本安装器 `npm run install:editions`，要求校园版、企业版和金融版三个域名，并会同时构建、安装和启动三套 API。仓库没有独立的一键金融版安装脚本。若只上线金融版，可按本指南中对应的构建、systemd 和 Apache 配置手动安装；如需自动化安装，请使用完整三版本流程。

## 1. 金融版服务信息

| 项目 | 配置 |
| --- | --- |
| 前端构建目录 | `dist-finance` |
| 应用版本标识 | `finance` |
| API 端口 | `8789`，仅本机监听/供反向代理访问 |
| systemd 服务 | `ailunwen-finance-api.service` |
| 独立环境文件 | `/home/ubuntu/ailunwen-secrets/ailunwen-finance.env` |
| 健康检查 | `/api/health` |
| 数据库 | 生产环境使用 PostgreSQL；金融订阅记录在 `finance_subscriptions` 表 |

金融版和其他版本共用用户及 PostgreSQL 数据库时，务必配置相同的 `JWT_SECRET` 和 `DATABASE_URL`。聊天记录按版本隔离。金融网页检索会包含代码配置的公开金融信息来源，依赖已配置的搜索服务和上游网站可用性；它不要求或调用需授权的 Wind 终端接口。

## 2. 部署前准备

- Ubuntu 服务器，建议使用 Node.js 20 或 22 LTS、npm、Git、Apache 2 和 PostgreSQL。
- 一个解析到服务器的金融版域名，例如 `finance.example.com`。
- 已准备生产 PostgreSQL 数据库、可访问的数据库账号和备份策略。
- 防火墙仅向公网开放 SSH 管理端口及 Web 的 80/443；不要开放 8789 或 PostgreSQL 端口。
- 如启用微信扫码登录或微信支付，先准备相应的开放平台/商户平台应用和生产证书。登录 AppID 与支付 AppID 是两套不同配置。

下面的自动部署步骤假设本机 Apache 和 PostgreSQL 已安装。基础环境可参考仓库的 [Ubuntu 24.04 本机部署教程](本机部署教程-Ubuntu24.04.md)。

## 3. 获取代码

```bash
cd /home/ubuntu
git clone https://github.com/Lemon000912/CST.git ailunwen
cd /home/ubuntu/ailunwen
npm ci
```

已有代码目录时，先检查本地修改，再切换到准备发布的提交。不要覆盖尚未保存的运维改动。

## 4. 设置生产环境和管理员

创建仅部署账户可读的私密目录和金融版环境文件：

```bash
sudo install -d -m 700 -o ubuntu -g ubuntu /home/ubuntu/ailunwen-secrets
nano /home/ubuntu/ailunwen-secrets/ailunwen.env
nano /home/ubuntu/ailunwen-secrets/ailunwen-finance.env
```

公共环境文件 `/home/ubuntu/ailunwen-secrets/ailunwen.env` 至少设置：

```dotenv
NODE_ENV=production
DATABASE_URL=postgresql://数据库用户:数据库密码@127.0.0.1:5432/数据库名
JWT_SECRET=替换为至少32字符的随机密钥
ADMIN_USERNAMES=financeadmin
```

生成随机密钥：

```bash
openssl rand -base64 48
```

金融版独立环境文件设置专用管理员账号。首次启动时，应用只在该账号尚不存在时创建账号，不会覆盖已有密码：

```dotenv
FINANCE_ADMIN_USERNAME=financeadmin
FINANCE_ADMIN_PASSWORD=替换为至少12位的强密码
```

如果其他版本共用用户表，`ADMIN_USERNAMES` 是允许进入管理接口的账号白名单；将实际使用的管理员用户名加入列表。首次登录后立即确认密码，并按组织策略轮换。

金融版基础依赖微信支付。正式支付需要在金融版进程可读的环境文件中设置以下参数：

```dotenv
PAYMENT_NOTIFY_BASE_URL=https://finance.example.com
WECHAT_PAY_APP_ID=微信支付应用AppID
WECHAT_PAY_MCH_ID=商户号
WECHAT_PAY_MCH_SERIAL_NO=商户API证书序列号
WECHAT_PAY_API_V3_KEY=恰好32字节的APIv3密钥
WECHAT_PAY_PRIVATE_KEY_PATH=/home/ubuntu/wechatpay/cert/apiclient_key.pem
WECHAT_PAY_PUBLIC_KEY_PATH=/home/ubuntu/wechatpay/cert/pub_key.pem
WECHAT_PAY_PUBLIC_KEY_ID=PUB_KEY_ID_开头的公钥ID
WECHAT_PAY_NOTIFY_URL=https://finance.example.com/api/pay/wechat/notify
WECHAT_PAY_TEST_MODE=false
```

`apiclient_key.pem` 和微信支付公钥应保存在代码仓库之外的私密目录。限制文件权限，并确保运行服务的 Linux 账号可读私钥和公钥。`WECHAT_PAY_API_V3_KEY` 必须为 32 字节；生产回调地址必须为 HTTPS。不要在生产环境启用测试支付模式。金融版套餐价格由应用配置提供：月度 980 元、季度 2680 元、半年 4980 元、年度 7980 元；发布前应与实际销售政策核对。

如启用微信扫码登录，再按 `.env.example` 配置 `WECHAT_OPEN_APP_ID`、`WECHAT_OPEN_APP_SECRET`、`FINANCE_WECHAT_OPEN_REDIRECT_URI` 和 `FINANCE_WECHAT_OPEN_FRONTEND_URL`。开放平台登记的回调域必须匹配实际 HTTPS 配置。扫码登录配置与微信支付证书配置互不替代。

设置权限：

```bash
chmod 600 /home/ubuntu/ailunwen-secrets/ailunwen.env
chmod 600 /home/ubuntu/ailunwen-secrets/ailunwen-finance.env
```

生产环境不要把真实密码、JWT 密钥、支付密钥或证书提交到 Git，也不要将支付证书放在可由 Apache 公开读取的静态目录。

## 5. 部署方式 A：使用仓库三版本安装器

此方式适用于同一服务器同时部署三个版本的情况。先确保校园版和企业版域名也已规划并解析，然后在仓库目录运行：

```bash
cd /home/ubuntu/ailunwen
SCHOOL_DOMAIN=school.example.com \
ENTERPRISE_DOMAIN=enterprise.example.com \
FINANCE_DOMAIN=finance.example.com \
npm run install:editions
```

安装器执行三版本构建，写入 Apache 与 systemd 配置，并启动校园版、企业版、金融版 API 和共享 PDF 同步服务。金融 API 服务名为 `ailunwen-finance-api.service`，端口为 8789。

为金融域名配置 HTTPS。使用 Apache 与 Certbot 的示例：

```bash
sudo apt update
sudo apt install -y certbot python3-certbot-apache
sudo certbot --apache -d finance.example.com
```

如果三个版本均部署，可在同一次 Certbot 命令中加入其他域名。安装器生成的站点初始监听 HTTP 80；证书签发后确认 Apache 已将金融站点 HTTP 请求重定向到 HTTPS，并验证 HTTPS 访问。

## 6. 部署方式 B：只部署金融版

单版本部署需要手动安装 API 服务和 Apache 虚拟主机，因为仓库自动安装器面向三个版本。以下示例假设项目目录为 `/home/ubuntu/ailunwen`，服务运行用户为 `ubuntu`，Node 可执行文件位于 `/usr/bin/node`；按服务器实际路径调整。

先构建金融版：

```bash
cd /home/ubuntu/ailunwen
npm run build:finance
```

安装 systemd 服务：

```bash
sudo cp deploy/ailunwen-finance-api.service /etc/systemd/system/ailunwen-finance-api.service
```

仓库中的 unit 模板含 `%WORKDIR%` 等占位符，需要替换后再启用：

```bash
sudo sed \
  -e 's|%WORKDIR%|/home/ubuntu/ailunwen|g' \
  -e 's|%NODE_BIN%|/usr/bin|g' \
  -e 's|%USER%|ubuntu|g' \
  -e 's|%SECRETS_DIR%|/home/ubuntu/ailunwen-secrets|g' \
  /home/ubuntu/ailunwen/deploy/ailunwen-finance-api.service \
  | sudo tee /etc/systemd/system/ailunwen-finance-api.service >/dev/null
sudo systemctl daemon-reload
sudo systemctl enable --now ailunwen-finance-api.service
```

添加 Apache 金融站点。启用 `proxy`、`proxy_http`、`rewrite`、`headers` 模块；保存以下配置到 `/etc/apache2/sites-available/ailunwen-finance.conf`，将域名和路径替换为实际值：

```apache
<VirtualHost *:80>
    ServerName finance.example.com
    DocumentRoot /home/ubuntu/ailunwen/dist-finance

    <Directory /home/ubuntu/ailunwen/dist-finance>
        Options -Indexes +FollowSymLinks
        AllowOverride All
        Require all granted
        FallbackResource /index.html
    </Directory>

    ProxyPreserveHost On
    RequestHeader set X-Forwarded-Proto "http"
    ProxyPass /api http://127.0.0.1:8789/api connectiontimeout=5 timeout=900
    ProxyPassReverse /api http://127.0.0.1:8789/api
    ProxyPass /admin http://127.0.0.1:8789/admin connectiontimeout=5 timeout=900
    ProxyPassReverse /admin http://127.0.0.1:8789/admin
    LimitRequestBody 110100480

    ErrorLog ${APACHE_LOG_DIR}/ailunwen-finance-error.log
    CustomLog ${APACHE_LOG_DIR}/ailunwen-finance-access.log combined
</VirtualHost>
```

启用站点并检查配置：

```bash
sudo a2enmod proxy proxy_http rewrite headers
sudo a2ensite ailunwen-finance.conf
sudo apache2ctl configtest
sudo systemctl reload apache2
sudo certbot --apache -d finance.example.com
```

若服务器已有默认站点或其他虚拟主机，确认域名只匹配预期站点。应用端口仍仅对本机反代开放，不要为 8789 增加公网防火墙规则。

## 7. 部署验收

检查服务状态和本机健康接口：

```bash
sudo systemctl status ailunwen-finance-api.service --no-pager
curl -fsS http://127.0.0.1:8789/api/health
curl -fsS https://finance.example.com/api/health
```

健康接口返回内容中的 `edition` 应为 `finance`。随后用浏览器确认：

1. 金融版首页、静态资源和前端路由正常加载。
2. 用户登录成功；若启用扫码登录，回调后返回金融版域名。
3. 金融版检索、PDF 上传/访问按产品配置正常工作。
4. 订阅套餐显示正确；支付配置有效时可创建微信支付订单，支付回调成功后订阅有效期有更新。
5. 普通用户无法访问管理接口；已授权的金融管理员可以使用管理功能。

支付上线前使用微信支付商户平台和小额/测试环境核对下单、回调验签、重复回调幂等处理、退款及对账流程。不能仅凭页面显示“支付成功”判定回调链路已验收。

## 8. 更新与回滚

拉取发布提交、安装依赖并重新构建金融前端：

```bash
cd /home/ubuntu/ailunwen
git status --short
git pull --ff-only
npm ci
npm run build:finance
sudo systemctl restart ailunwen-finance-api.service
sudo systemctl reload apache2
```

如后端依赖没有变化，可跳过 `npm ci`。本地单金融版流程不应使用 `npm run update:editions`，因为该脚本会构建并重启全部三个版本。发布后重复健康检查和关键登录/支付验收。保留上一个可用提交及数据库备份，以便故障时恢复代码和数据。

## 9. 日志、备份与故障排查

```bash
sudo journalctl -u ailunwen-finance-api.service -n 100 --no-pager
sudo journalctl -u ailunwen-finance-api.service -f
sudo tail -n 100 /var/log/apache2/ailunwen-finance-error.log
sudo systemctl status postgresql --no-pager
```

数据库应进行定期、可恢复验证的 PostgreSQL 备份，并将备份存放在与应用服务器隔离且受控的位置。更新数据库结构前也应先完成备份。监控磁盘空间、CPU/内存、应用错误日志、API 健康接口、HTTPS 证书有效期及 PostgreSQL 可用性。

常见问题：

- **服务启动失败或数据库表缺失：**检查 `DATABASE_URL`、数据库连通性和日志。生产模式配置 PostgreSQL 后，连接失败时应用应启动失败，不应当作 SQLite 正常运行。
- **支付配置不可用：**检查 API 服务可读的支付 PEM 文件路径和权限、32 字节 APIv3 密钥、公钥 ID、商户证书序列号以及 HTTPS 通知 URL；修改 env 后重启金融 API。
- **支付成功但订阅未生效：**检查微信支付通知 URL 是否能从公网访问，Apache 是否将 `/api/pay/wechat/notify` 转发至 8789，服务日志中的验签/通知处理错误，并在商户平台核对交易状态。
- **扫码登录跳转到错误域名：**检查开放平台授权回调域、金融版 redirect URI、frontend URL 及 HTTPS 配置。
- **站点可打开但 API 失败：**检查 Apache 代理端口是否为 8789、`ailunwen-finance-api.service` 状态及健康接口。
- **金融网站检索无结果：**检查搜索服务配置、金融版后端是否收到请求，以及上游公开站点和搜索服务是否限流或不可用。

## 10. 金融生产环境控制建议

本指南描述应用的部署方式，不代表系统已通过金融监管、等保、渗透测试或支付机构审计。正式对客前，应由部署方结合适用要求完成身份与权限审查、密钥管理、传输加密、备份恢复演练、操作审计、漏洞修复和支付对账等控制，并确认数据留存和第三方服务使用符合组织要求。
