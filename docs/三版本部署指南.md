# 校园版、企业版与数智通金融版部署指南

本文说明如何在一台 Ubuntu 服务器上部署校园版、企业版和数智通金融版。三个版本使用同一套代码、三个独立域名、三个独立 API 进程，并共用 PostgreSQL 数据库和用户账号。

## 1. 版本与端口

| 版本 | 前端目录 | API 端口 | 开发前端端口 | 固定版本标识 |
| --- | --- | ---: | ---: | --- |
| 校园版 | `dist-school` | `8787` | `5175` | `school` |
| 企业版 | `dist-enterprise` | `8788` | `5176` | `enterprise` |
| 数智通金融 | `dist-finance` | `8789` | `5177` | `finance` |

生产环境由 Apache 根据域名提供静态前端，并将 `/api` 和 `/admin` 代理到相应 API 端口。网站业务对外使用 HTTP/HTTPS（80、443）；8787、8788、8789 不要对公网开放，服务器管理所需的 SSH 等端口按实际运维需要配置。

企业版和数智通金融版的搜索、图表和 PDF 操作不扣积分，校园版沿用积分计费。金融版保留网页与数据库检索；网页检索由后端固定追加东方财富网和万得公开页面站点搜索，不需要前台勾选，也不连接需授权的 Wind 终端接口。金融版不显示“其他数据库”知识库入口。三个版本共用数据库和账号，但聊天记录按版本隔离。

## 2. 部署前准备

准备一台 Ubuntu 服务器，并完成以下事项：

- 安装 Node.js、npm、Git、Apache 2 和 PostgreSQL 客户端；建议使用 Node.js 20 或 22 LTS。
- 准备三个已解析到此服务器的域名，例如 `school.example.com`、`enterprise.example.com`、`finance.example.com`。
- 确认 PostgreSQL 已运行，并准备好三个 API 共用的数据库连接串。
- 确认服务器对外允许 80、443 端口；内部 API 端口不对公网开放。

如果服务器尚未安装 PostgreSQL、Apache 或配置应用目录，可先按仓库中的 [Ubuntu 24.04 本机部署教程](本机部署教程-Ubuntu24.04.md) 完成基础环境，再继续本文。

## 3. 获取代码并安装依赖

将仓库克隆到固定目录。以下以 `/home/ubuntu/ailunwen` 为例；后续命令均在该目录执行：

```bash
cd /home/ubuntu
git clone https://github.com/Lemon000912/CST.git ailunwen
cd /home/ubuntu/ailunwen
npm ci
```

如果服务器已经有该仓库，则进入现有目录并先检查工作区，再拉取需要部署的分支或提交。不要在存在未保存的本地改动时直接覆盖。

## 4. 配置服务器私密环境变量

安装脚本默认从 `/home/ubuntu/ailunwen-secrets/ailunwen.env` 读取公共配置；每个版本还可从同目录下对应的 `ailunwen-school.env`、`ailunwen-enterprise.env`、`ailunwen-finance.env` 读取独立配置。创建目录和公共配置文件：

```bash
sudo install -d -m 700 -o ubuntu -g ubuntu /home/ubuntu/ailunwen-secrets
nano /home/ubuntu/ailunwen-secrets/ailunwen.env
```

至少配置生产数据库和强随机 JWT 密钥：

```dotenv
NODE_ENV=production
DATABASE_URL=postgresql://数据库用户:数据库密码@127.0.0.1:5432/数据库名
JWT_SECRET=替换为至少32字符的随机密钥
ADMIN_USERNAMES=admin,financeadmin
```

JWT 密钥可用以下命令生成，再把结果填入环境文件：

```bash
openssl rand -base64 48
```

把真实的数据库密码和服务密钥仅放在服务器私密环境文件中，勿提交到 Git。保存后设置权限：

```bash
chmod 600 /home/ubuntu/ailunwen-secrets/ailunwen.env
```

按需将 LLM、网页搜索、短信及其他第三方服务的配置加入公共文件或对应版本文件。变量清单和说明见仓库根目录 `.env.example`。因为三个版本共用 PostgreSQL，务必为三个 API 填写相同的 `DATABASE_URL` 和 `JWT_SECRET`。

企业版和金融版首次启动时会创建默认管理员 `admin` / `admin123`（仅当账号不存在时，不会覆盖已有账号）。生产部署前必须在对应版本文件中设置安全密码。由于三个版本共用用户表，企业版和金融版如果需要独立管理员，应使用不同用户名，并加入 `ADMIN_USERNAMES` 管理员白名单：

```dotenv
# ailunwen-enterprise.env
ENTERPRISE_ADMIN_USERNAME=admin
ENTERPRISE_ADMIN_PASSWORD=替换为企业版初始密码

# ailunwen-finance.env
FINANCE_ADMIN_USERNAME=financeadmin
FINANCE_ADMIN_PASSWORD=替换为金融版初始密码
```

首次启动会在共享用户表中创建这两个账号；如果 `admin` 已经存在，企业版不会重置它的密码。保存独立文件后设置为仅部署用户可读：

```bash
chmod 600 /home/ubuntu/ailunwen-secrets/ailunwen-enterprise.env
chmod 600 /home/ubuntu/ailunwen-secrets/ailunwen-finance.env
```

## 5. 构建并安装三个版本

在仓库目录执行安装命令，替换为自己的域名：

```bash
cd /home/ubuntu/ailunwen
SCHOOL_DOMAIN=school.example.com \
ENTERPRISE_DOMAIN=enterprise.example.com \
FINANCE_DOMAIN=finance.example.com \
npm run install:editions
```

安装脚本会先执行三版本构建，然后生成 Apache 虚拟主机和 systemd 服务，启动以下服务：

- `ailunwen-school-api.service`：校园版 API，端口 8787。
- `ailunwen-enterprise-api.service`：企业版 API，端口 8788。
- `ailunwen-finance-api.service`：数智通金融 API，端口 8789。
- `ailunwen-pdf-sync.service`：共用 PDF 库同步任务。
- `apache2.service`：三个域名的静态页面与反向代理。

部署后分别配置 HTTPS。使用 Apache 与 Certbot 时，可为三个域名申请证书：

```bash
sudo apt update
sudo apt install -y certbot python3-certbot-apache
sudo certbot --apache \
  -d school.example.com \
  -d enterprise.example.com \
  -d finance.example.com
```

证书签发完成后，在浏览器中分别访问三个 HTTPS 地址确认页面和 API 都可用。

## 6. 检查部署状态

查看服务状态：

```bash
sudo systemctl status ailunwen-school-api.service --no-pager
sudo systemctl status ailunwen-enterprise-api.service --no-pager
sudo systemctl status ailunwen-finance-api.service --no-pager
sudo systemctl status ailunwen-pdf-sync.service --no-pager
sudo systemctl status apache2 --no-pager
```

检查本机健康接口。返回 JSON 中的 `edition` 应分别是 `school`、`enterprise` 和 `finance`：

```bash
curl -fsS http://127.0.0.1:8787/api/health
curl -fsS http://127.0.0.1:8788/api/health
curl -fsS http://127.0.0.1:8789/api/health
```

也可以通过域名检查 Apache 代理和线上 HTTPS：

```bash
curl -fsS https://school.example.com/api/health
curl -fsS https://enterprise.example.com/api/health
curl -fsS https://finance.example.com/api/health
```

## 7. 配置微信扫码登录

三个版本可以共用微信开放平台网站应用和 AppID。将密钥只写入服务器环境文件，并为每个版本填写正确的登录回调及前端地址。若共用校园版回调域，示例：

```dotenv
WECHAT_OPEN_APP_ID=微信开放平台AppID
WECHAT_OPEN_APP_SECRET=微信开放平台AppSecret

SCHOOL_WECHAT_OPEN_REDIRECT_URI=https://school.example.com/api/v1/auth/wechat/callback
SCHOOL_WECHAT_OPEN_FRONTEND_URL=https://school.example.com/

ENTERPRISE_WECHAT_OPEN_REDIRECT_URI=https://school.example.com/api/v1/auth/wechat/callback
ENTERPRISE_WECHAT_OPEN_FRONTEND_URL=https://enterprise.example.com/

FINANCE_WECHAT_OPEN_REDIRECT_URI=https://school.example.com/api/v1/auth/wechat/callback
FINANCE_WECHAT_OPEN_FRONTEND_URL=https://finance.example.com/

WECHAT_OPEN_COOKIE_DOMAIN=example.com
WECHAT_OPEN_ENTERPRISE_CALLBACK_URI=https://enterprise.example.com/api/v1/auth/wechat/callback
WECHAT_OPEN_FINANCE_CALLBACK_URI=https://finance.example.com/api/v1/auth/wechat/callback
```

微信开放平台中必须登记实际使用的授权回调域。若企业版或金融版使用完全不同的主域，需按 `.env.example` 配置对应的固定中继地址；生产登录必须使用 HTTPS。独立 AppID 也可以分别配置各自的回调域。

## 8. 更新代码

更新前确认工作区没有需要保留的本地修改，然后拉取目标提交。重新安装依赖（仅在依赖文件发生变化时需要）并运行更新脚本：

```bash
cd /home/ubuntu/ailunwen
git pull --ff-only
npm ci
npm run update:editions
```

更新脚本会重建三个前端并重启三个 API、PDF 同步任务和 Apache。完成后重复第 6 节的健康检查。

## 9. 查看日志与排查

查看指定版本的最近日志或持续跟踪：

```bash
sudo journalctl -u ailunwen-school-api.service -n 100 --no-pager
sudo journalctl -u ailunwen-enterprise-api.service -n 100 --no-pager
sudo journalctl -u ailunwen-finance-api.service -n 100 --no-pager
sudo journalctl -u ailunwen-finance-api.service -f
```

常见检查点：

- 健康接口的 `edition` 不正确：检查请求是否代理到对应端口，以及该端口上的 systemd 服务是否为对应版本。
- 页面能打开但 API 报错：确认 Apache 虚拟主机的域名、API 代理端口和 Node 服务状态。
- PostgreSQL 启动失败：检查所有版本共同读取的 `DATABASE_URL`、数据库网络和账号权限；生产环境连接失败时服务会报错退出，不应降级到 SQLite。
- 微信登录跳转错误：核对开放平台登记回调域、`*_WECHAT_OPEN_REDIRECT_URI`、`*_WECHAT_OPEN_FRONTEND_URL` 与固定中继回调地址，并确认 HTTPS 证书正常。
- 金融版网页检索未显示东方财富网或万得结果：确认请求到达端口 8789 的金融版后端，并在金融版选择“网页”频道；两个站点使用公开网页站点限定搜索，结果数量取决于搜索引擎收录和当前可用性。检索到网页条目不代表网页正文已抓取成功：正文抓取只处理排序后的候选页面，每次最多 20 页；检查 `search.web_page_fetch.item` 日志中的 `urlHost` 和 `ok`，确认具体网站是否抓取成功。搜索引擎或内容解锁服务出现余额不足、限流、403 等情况时，也会造成部分来源无结果或无法读取正文。

若使用 Nginx，仓库提供 `deploy/nginx-ailunwen-editions.conf` 作为三域名反向代理模板；自动安装脚本当前使用 Apache，不会自动安装或启用 Nginx。Nginx 部署时需替换模板中的域名和项目绝对路径，并由管理员自行安装、校验和重载 Nginx。
