# 扫码充值支付开通指南

> 适用项目：积分充值（100 元兑换 1000 积分）  
> 支付方式：支付宝订单码支付、微信支付 Native 支付  
> 文档日期：2026-08-14  
> 注意：支付平台的审核材料和菜单名称可能调整，最终以商户后台显示为准。

## 1. 目标支付流程

```text
用户登录网站
→ 点击“充值”
→ 选择支付宝或微信支付
→ 网站弹出 100 元付款二维码
→ 用户使用手机扫码付款
→ 支付平台异步通知服务器
→ 服务器验签并核对订单金额
→ 自动增加 1000 积分
```

支付平台对应产品：

| 支付平台 | 需要开通的产品 | 后端接口/模式 |
|---|---|---|
| 支付宝 | 当面付 → 订单码支付 | `alipay.trade.precreate` |
| 微信支付 | Native 支付 | 微信支付 API v3 Native 下单 |

支付宝后台不要选择“电脑网站支付”。电脑网站支付会跳转到支付宝官方收银台，不符合当前“站内弹窗直接显示二维码”的交互。

## 2. 开通前共同准备材料

建议使用企业或个体工商户主体申请支付能力。

### 2.1 主体资料

- [ ] 营业执照彩色扫描件或清晰照片
- [ ] 法定代表人/经营者身份证正反面
- [ ] 企业对公银行账户，或个体工商户经营者银行卡
- [ ] 企业名称、统一社会信用代码、注册地址
- [ ] 实际经营地址
- [ ] 支付业务联系人姓名、手机号、邮箱
- [ ] 客服电话或在线客服联系方式

### 2.2 网站资料

- [ ] 已注册的业务域名
- [ ] 中国大陆服务器所需的 ICP 备案
- [ ] 公网可访问的 HTTPS 网站
- [ ] 有效且完整的 HTTPS 证书链
- [ ] 网站首页和产品页面截图
- [ ] 充值页面截图，清楚展示“100 元 = 1000 积分”
- [ ] 服务内容说明，例如文献检索、AI 回答、图表和 PDF 服务
- [ ] 用户协议
- [ ] 隐私政策
- [ ] 充值与退款规则
- [ ] 客服及投诉入口

### 2.3 积分业务说明

建议在用户协议和充值页面明确：

> 积分仅用于抵扣本平台提供的文献检索、AI 回答、图表、PDF 等服务费用，不可提现、不可转账、不可在用户之间交易。

经营内容和营业执照经营范围应尽量覆盖软件服务、信息技术服务、互联网信息服务或与平台实际业务相符的范围。不得向支付平台隐瞒实际经营内容。

## 3. 公网服务器和回调地址

假设正式域名是：

```text
https://paper.example.com
```

项目使用以下异步通知地址：

```text
https://paper.example.com/api/v1/billing/recharge/callback/alipay
https://paper.example.com/api/v1/billing/recharge/callback/wechat
```

服务器检查清单：

- [ ] 域名已经解析到正式服务器
- [ ] HTTPS 证书有效且浏览器无安全警告
- [ ] Nginx/反向代理将 `/api/` 转发到 Node API 服务
- [ ] 回调地址不需要用户登录或 JWT
- [ ] 回调地址未被验证码、登录页或 WAF 人机验证拦截
- [ ] CDN/反向代理不缓存支付回调
- [ ] 代理不会修改微信回调的原始 JSON 请求体
- [ ] 服务器时间已经启用 NTP 自动同步
- [ ] 防火墙允许支付平台通过 HTTPS 访问回调地址

公共环境变量：

```env
NODE_ENV=production
PAYMENT_NOTIFY_BASE_URL=https://paper.example.com
```

`PAYMENT_NOTIFY_BASE_URL` 只填写域名和协议，不填写回调路径，末尾不要添加 `/`。

## 4. 支付宝订单码支付开通步骤

官方入口：

- [订单码支付产品说明](https://opendocs.alipay.com/open/05osux)
- [订单码支付接入准备](https://opendocs.alipay.com/open/05osuy)
- [订单码支付开通页面](https://b.alipay.com/page/product-mall/product-detail/I1080300001000041313)
- [支付宝开发者控制台](https://open.alipay.com/develop/manage)

### 4.1 注册并认证支付宝商家

1. 注册企业支付宝或个体工商户支付宝账号。
2. 完成企业/经营者实名认证。
3. 绑定结算账户。
4. 确保支付宝账号主体与营业执照主体一致。

### 4.2 准备订单码支付审核材料

支付宝订单码支付官方目前列出的材料包括：

- [ ] 经营场所招牌照片
- [ ] 经营场所内景照片
- [ ] 店铺名称或经营品牌名称
- [ ] 实际经营地址
- [ ] 营业执照
- [ ] 网站、充值页面和服务内容截图
- [ ] 100 元/1000 积分价格说明

订单码支付偏向门店收银、订单二维码和媒体广告场景。没有实际经营场所时可能无法通过审核，应根据支付宝审核意见决定是否改为“电脑网站支付”。如果改为电脑网站支付，当前后端接口也需要同步调整。

### 4.3 申请订单码支付

1. 登录支付宝商家平台。
2. 打开“当面付/订单码支付”产品页面。
3. 点击“立即开通”。
4. 填写经营行业、经营地址、品牌和网站信息。
5. 上传要求的主体和经营场所材料。
6. 提交审核。
7. 审核通过后确认产品状态为“已签约/已开通”。

支付宝订单码支付常见费率约为 0.6%～1%，最终以签约页面和实际行业为准。

### 4.4 创建支付宝网页应用

1. 登录支付宝开发者控制台。
2. 进入“网页/移动应用”。
3. 创建网页应用。
4. 填写应用名称、图标、网站地址和业务说明。
5. 提交应用审核。
6. 将已签约的订单码支付产品绑定到应用。
7. 确认应用可以调用正式环境接口。
8. 记录应用的 `APP_ID`。

### 4.5 生成和配置 RSA2 密钥

当前项目使用“普通公钥模式 + RSA2 2048 位”，暂未使用支付宝证书模式。

1. 使用支付宝开放平台开发助手生成 RSA2 2048 位密钥。
2. 安全保存“应用私钥”。
3. 将“应用公钥”上传到支付宝应用控制台。
4. 上传完成后复制或下载控制台提供的“支付宝公钥”。
5. 在商家后台记录支付宝商户 PID/Seller ID，通常以 `2088` 开头。

必须区分：

| 名称 | 用途 | 是否配置到项目 |
|---|---|---|
| 应用私钥 | 项目请求支付宝时签名 | 是 |
| 应用公钥 | 上传给支付宝验证项目签名 | 否，只上传到支付宝 |
| 支付宝公钥 | 项目验证支付宝响应和通知 | 是 |

建议保存为：

```text
/run/secrets/alipay_app_private_key.pem
/run/secrets/alipay_public_key.pem
```

正式环境配置：

```env
ALIPAY_APP_ID=支付宝应用APP_ID
ALIPAY_PRIVATE_KEY_FILE=/run/secrets/alipay_app_private_key.pem
ALIPAY_PUBLIC_KEY_FILE=/run/secrets/alipay_public_key.pem
ALIPAY_SELLER_ID=以2088开头的支付宝商户PID
```

生产环境不要配置 `ALIPAY_GATEWAY_URL`，项目会自动使用支付宝正式网关。只有明确进行沙箱联调时才配置沙箱网关，但订单码支付是否支持当前沙箱能力应以支付宝后台为准。

### 4.6 支付宝完成检查

- [ ] 支付宝商家实名认证完成
- [ ] 订单码支付已签约
- [ ] 网页应用已审核并可调用正式接口
- [ ] 订单码支付已绑定应用
- [ ] 使用普通公钥模式
- [ ] 应用公钥已上传支付宝
- [ ] 应用私钥已安全保存
- [ ] 支付宝公钥已下载
- [ ] APP_ID 和 Seller ID 已记录

## 5. 微信 Native 支付开通步骤

官方入口：

- [微信支付商户平台](https://pay.weixin.qq.com/)
- [微信支付商户文档](https://pay.weixin.qq.com/doc/v3/merchant/)

### 5.1 注册微信支付商户号

1. 登录微信支付商户平台并申请成为商户。
2. 提交营业执照、法人/经营者身份证和结算账户。
3. 填写联系人、经营行业、网站和客服信息。
4. 完成账户验证和签约。
5. 审核通过后记录微信支付商户号 `MCH_ID`。

### 5.2 准备并绑定 AppID

微信 Native 下单仍然需要一个已经绑定商户号的 AppID。通常可以使用：

- 已认证微信服务号 AppID
- 已认证微信小程序 AppID
- 微信开放平台移动应用 AppID

操作步骤：

1. 准备已认证、主体一致或可授权绑定的 AppID。
2. 登录微信支付商户平台。
3. 进入“产品中心/开发配置/AppID 账号管理”（以后台实际菜单为准）。
4. 发起 AppID 与商户号绑定。
5. 在对应公众平台、开放平台或小程序后台确认绑定授权。
6. 记录 `WECHAT_PAY_APP_ID`。

### 5.3 开通 Native 支付

1. 登录微信支付商户平台。
2. 进入“产品中心”。
3. 找到“Native 支付”。
4. 点击申请开通。
5. 填写网站地址、经营内容、商品/服务价格和付款场景。
6. 上传网站页面、充值页面和服务说明截图。
7. 提交审核。
8. 审核通过后确认 Native 支付状态为“已开通”。

当前扫码方案不要求另外开通 JSAPI、H5、小程序或 APP 支付，除非以后需要在对应客户端内直接拉起付款。

### 5.4 设置 APIv3 密钥

1. 进入“账户中心 → API 安全”。
2. 设置 APIv3 密钥。
3. 密钥必须严格为 32 字节。
4. 立即存入服务器秘密管理系统。

```env
WECHAT_PAY_API_V3_KEY=严格32字节的APIv3密钥
```

APIv3 密钥用于解密支付通知。平台一般不会再次明文展示，遗失后通常只能重置。

### 5.5 申请商户 API 证书

在微信支付商户平台“API 安全”中申请商户 API 证书，保存：

```text
apiclient_key.pem
apiclient_cert.pem
```

项目运行时需要商户私钥 `apiclient_key.pem`，同时需要记录商户证书序列号。

查看商户证书序列号：

```bash
openssl x509 -in apiclient_cert.pem -noout -serial
```

配置时去掉输出中的 `serial=` 前缀：

```env
WECHAT_PAY_MERCHANT_SERIAL_NO=商户API证书序列号
WECHAT_PAY_PRIVATE_KEY_FILE=/run/secrets/apiclient_key.pem
```

### 5.6 配置微信支付平台公钥

微信支付平台公钥用于验证微信支付的下单响应和异步通知。

如果使用微信支付公钥模式：

1. 在微信支付商户平台下载微信支付公钥 PEM 文件。
2. 记录对应的微信支付公钥 ID，通常类似 `PUB_KEY_ID_xxx`。

```env
WECHAT_PAY_PLATFORM_PUBLIC_KEY_FILE=/run/secrets/wechatpay_public_key.pem
WECHAT_PAY_PLATFORM_SERIAL_NO=PUB_KEY_ID_xxxxxxxxx
```

如果商户使用平台证书模式：

1. 下载有效的微信支付平台证书。
2. 保存平台证书 PEM 文件。
3. 记录平台证书序列号。

```env
WECHAT_PAY_PLATFORM_PUBLIC_KEY_FILE=/run/secrets/wechatpay_platform_cert.pem
WECHAT_PAY_PLATFORM_SERIAL_NO=平台证书序列号
```

### 5.7 微信完整环境配置

```env
WECHAT_PAY_APP_ID=wx开头的AppID
WECHAT_PAY_MCH_ID=微信支付商户号
WECHAT_PAY_MERCHANT_SERIAL_NO=商户API证书序列号
WECHAT_PAY_PRIVATE_KEY_FILE=/run/secrets/apiclient_key.pem
WECHAT_PAY_PLATFORM_PUBLIC_KEY_FILE=/run/secrets/wechatpay_public_key.pem
WECHAT_PAY_PLATFORM_SERIAL_NO=微信支付公钥ID或平台证书序列号
WECHAT_PAY_API_V3_KEY=严格32字节的APIv3密钥
```

- [ ] AppID 已认证
- [ ] AppID 已绑定商户号并确认授权

## 6. 密钥保存规范

生产服务器建议设置：

```bash

chmod 600 /run/secrets/alipay_public_key.pem
chmod 600 /run/secrets/apiclient_key.pem
```

安全要求：

- [ ] 私钥不放在项目目录
- [ ] 私钥不提交 Git
- [ ] 私钥不写入 `.env.example`
- [ ] 私钥不通过微信、邮件、截图或聊天发送
- [ ] `.env` 不提交 Git
- [ ] 只有运行 Node 服务的系统用户可以读取密钥
- [ ] 生产密钥和测试密钥分离
- [ ] 密钥备份使用加密存储
- [ ] 建立密钥轮换和证书到期提醒

## 8. 部署与二维码生成验证

1. 将支付密钥安全上传到服务器秘密目录。
2. 将上述环境变量写入正式环境配置。
3. 确认生产环境继续使用 PostgreSQL。
4. 重启 Node API 服务。
5. 服务启动时确认数据库初始化成功。
6. 使用测试用户登录网站。
7. 点击“充值”。
8. 确认已配置的平台按钮可以选择。
9. 点击“生成付款二维码”。
10. 确认二维码金额为 100 元，商户名称正确。
11. 使用手机扫码支付。
12. 等待网页显示充值成功。
13. 确认用户余额增加 1000 积分。

二维码生成依赖支付平台真实下单：

```text
后端向支付平台提交订单
→ 支付平台验签并返回 qr_code/code_url
→ 项目使用 qrcode 库生成二维码图片
```

只填写假 APP_ID 或假密钥无法生成可付款二维码。

## 9. 数据库验收

支付成功后检查 PostgreSQL：

```sql
SELECT id, order_no, provider, amount_fen, point_units, status, paid_at
FROM point_recharge_orders
ORDER BY created_at DESC
LIMIT 10;
```

预期订单数据：

```text
amount_fen = 10000
point_units = 20000
status = paid
```

项目内部 `20 units = 1 积分`，所以 `20000 units = 1000 积分`。

检查充值流水：

```sql
SELECT user_id, entry_type, idempotency_key, delta_units, balance_after_units, created_at
FROM point_ledger
WHERE entry_type = 'recharge'
ORDER BY created_at DESC
LIMIT 10;
```

预期：

- `entry_type = recharge`
- `delta_units = 20000`
- 同一充值订单只有一条充值流水
- 支付平台重复通知不会重复增加积分

## 10. 上线前必须处理的业务事项

当前充值功能已经处理支付成功和重复回调，但正式开放前还应确认：

- [ ] 明确充值退款政策
- [ ] 明确未消费积分退款规则
- [ ] 明确开票方式
- [ ] 建立每日支付平台订单与本地订单对账流程
- [ ] 建立异常订单人工处理流程
- [ ] 建立证书和密钥到期提醒
- [ ] 建立客服投诉处理流程
- [ ] 为支付失败、回调延迟准备用户提示

当前代码尚未自动处理支付平台退款后的积分扣回。若直接从支付宝或微信商户后台退款，用户已到账积分不会自动扣除。正式开放退款功能前，需要增加退款订单、退款通知验签和负向积分流水。
